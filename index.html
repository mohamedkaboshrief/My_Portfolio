Car Price Prediction — Technical Breakdown & Pipeline

End-to-End Regression Pipeline & Model Optimization

Benchmarked 9 regression algorithms with 5-fold cross-validation and Target Encoding. Tuned Random Forest achieves R² = 0.7488, MedAE of 2,462.27, and the smallest generalization gap (0.145).

Explore Codebase

Dataset & Problem Framing

Trained on the Kaggle Car Price Prediction Challenge dataset containing 19,237 records and 18 columns before preprocessing. The goal is to build an end-to-end regression model capable of predicting the price of a used car based on vehicle characteristics such as production year, mileage, engine volume, fuel type, gearbox, drive wheels, and vehicle specifications. After preprocessing and encoding, the dataset contains 18,923 records and 52 columns (51 features plus target).

Data Cleaning & Feature Engineering Pipeline

  • Duplicate & Identifier Removal: Removed duplicate records and the uninformative ID column.
  • Missing-Value & Numerical Handling: Imputed missing entries and cleaned/converted formatted numerical features into appropriate quantitative types.
  • Categorical Combination: Merged car manufacturer and model information into a cohesive vehicle descriptor to preserve brand and model lineage.
  • High-Cardinality Target Encoding: Applied Target Encoding to the high-cardinality "Car" feature using Category Encoders (applied to full dataset before train/test split).
  • Low-Price Inspection & Outlier Management: Statistically analyzed 1,633 records (~8.6% of data) priced below 500. They shared the same median production year (2012) and moderate mileage (median ~149k km vs 125k km) and engine volume (2.4 vs 2.0), so they were retained without synthetic distortion. Removed an extreme price outlier.
  • Train / Test Split & Scaling: Partitioned using a 75/25 split. Standardized scale-sensitive models (SGD Regressor, Lasso, Ridge, KNN) using StandardScaler fitted strictly on the training set.

Model Comparison (5-Fold Cross-Validation on 9 Regressors)

Nine regression models were tuned using GridSearchCV with 5-Fold Cross-Validation and R² as the evaluation metric. Linear models performed far below tree-based algorithms, indicating non-linear relationships:

Model Algorithm Category Best CV R² Evaluation Notes
Linear Regression Linear Baseline 0.2623 Linear baseline; incapable of fitting non-linear depreciation curves
SGD Regressor Gradient Descent 0.2623 Iterative linear regression via SGD with standardized features
Lasso Regression (L1) Regularized Linear 0.2623 L1 regularization; bounded by linear assumptions
Ridge Regression (L2) Regularized Linear 0.2624 L2 regularization; slight multicollinearity mitigation
Random Forest Regressor ★ Ensemble Bagging 0.7175 Selected Winning Model — Achieved best test generalization & lowest overfitting gap
Gradient Boosting Regressor Ensemble Boosting 0.7581 Highest CV score; second highest test R² (0.7392) with larger train-test gap
XGBoost Regressor Gradient Boosting 0.7478 High training fit (0.9609) but lower test generalization (0.7151)
Decision Tree Regressor Tree-based 0.6434 Single tree partitioning; prone to high variance
K-Nearest Neighbors (KNN) Instance-based 0.5500 Normalized distance-weighted metric across continuous/encoded dimensions

Final Model Selection (Top 3 Test Set Evaluation)

The three models with highest cross-validation R² were evaluated on the held-out test set to select the production model:

Although Gradient Boosting achieved the highest CV score (0.7581), Random Forest Regressor was chosen as the final model because it achieved the highest test R² (0.7488) and the smallest generalization gap (0.145) between train and test scores, demonstrating superior robustness against overfitting.

  • min_samples_split: [5, 10]

The tuned Random Forest Regressor was evaluated on the held-out test set, achieving a Test R² of approximately 74.9%:

The MAE of 4,521.31 indicates that predictions deviate from actual car prices by approximately 4,521 on average in absolute terms. The substantially lower Median Absolute Error (≈ 2,462) demonstrates that the vast majority of predictions closely track real transaction values, with larger residuals primarily driven by rare, high-luxury vehicles. The Actual vs Predicted plot verified consistent alignment along the diagonal reference line across diverse price ranges.

Limitations & Methodology Notes

  • Target Encoding Leakage Consideration: The Target Encoding of the Car feature was fitted on the full dataset prior to train/test partitioning; fitting strictly within cross-validation folds represents an area for even stricter generalization guarantees.
  • Low-Priced Outliers: Unusually low prices (<500) were retained due to lack of an exclusionary empirical pattern, which naturally bounds the upper limit of achievable regression precision.

Telco Customer Churn — Technical Breakdown, Pipeline & Deployment

Live Interactive Streamlit Web App Deployed

Test the trained machine learning pipeline live: input customer attributes (tenure, contracts, internet services, charges) and receive instant churn predictions with calibrated probabilities.

Open Streamlit App

Dataset & Business Problem Framing

Trained on the Kaggle Telco Customer Churn dataset comprising 7,043 customer records and 21 features before preprocessing. The target variable is binary: Churn = 1 (Yes — customer churned) versus Churn = 0 (No — retained). Features span customer demographics, account tenure, phone and internet services, technical support, streaming add-ons, contract types, billing preferences, monthly charges, and total charges.

Recall Prioritization Rationale: In telecom subscription economics, failing to identify an actual churner (a False Negative) causes permanent recurring revenue loss and forfeited customer lifetime value. Conversely, an incorrect churn prediction (a False Positive) merely triggers proactive retention engagement, customer outreach, or loyalty incentives. Consequently, Recall for the churn class was prioritized throughout cross-validation, hyperparameter tuning, and threshold selection.

Exploratory Data Analysis (EDA) & Data Cleaning

Thorough EDA revealed key behavioral patterns and guided essential data cleaning decisions:

  • Numerical Distributions: Analyzed via histograms and boxplots. Customers with shorter tenure tend to churn noticeably more frequently. Likewise, higher monthly charges strongly correlate with increased churn likelihood.
  • Categorical & Bivariate Trends: Countplots and cross-tabulations demonstrated marked churn divergence across Contract types (Month-to-month shows high churn vs. Two-year), Internet Service (Fiber optic customers churn at higher rates), and Payment Method (Electronic check users have the highest churn rate).
  • Feature Pruning: During EDA, gender showed limited impact on churn with virtually identical churn distributions across cohorts. It was removed from the final feature set to simplify the model.

Data Cleaning Workflow:

  • Removed customerID identifier.
  • Converted TotalCharges to numeric, handling blank/whitespace values.
  • Set TotalCharges to 0 for customers with blank charges.
  • Set tenure to 0 when TotalCharges was 0.
  • Estimated missing tenure values using TotalCharges and MonthlyCharges.
  • Estimated missing MonthlyCharges using TotalCharges and tenure.
  • Replaced No internet service with No for the relevant service features.
  • Replaced No phone service with No in MultipleLines.
  • Removed duplicate rows.

Feature Preprocessing & Selection Pipeline

Features were systematically grouped and passed through a unified Scikit-learn ColumnTransformer and SelectKBest pipeline to ensure reproducible transformations with zero data leakage:

  • Binary Features (11): Partner, Dependents, PhoneService, MultipleLines, OnlineSecurity, OnlineBackup, DeviceProtection, TechSupport, StreamingTV, StreamingMovies, PaperlessBilling → Imputed and encoded.
  • Categorical Features (3): InternetService, Contract, PaymentMethod → Handled via OrdinalEncoder and OneHotEncoder.
  • Numerical Features (3): tenure, MonthlyCharges, TotalCharges → Scaled with StandardScaler after imputation.
  • Integrated Feature Selection: Implemented SelectKBest(score_func=f_classif) inside the cross-validation pipeline, evaluating k ∈ [5, 10, 15, 20, 'all'] to systematically pinpoint the most discriminative feature subset.
  • Stratified Train / Test Split: Partitioned 75% Training Data and 25% Test Data using a stratified split to preserve the natural churn class distribution across sets:
train_test_split( X, y, test_size=0.25, random_state=44, shuffle=True, stratify=y ) # Target mapping: Yes → 1, No → 0

Model Benchmarking (5-Fold Cross-Validation on 5 Classifiers)

Five classification algorithms were trained and tuned using GridSearchCV with 5-Fold Cross-Validation, optimizing specifically for Recall. Each model was implemented as an encapsulated Pipeline containing preprocessing, feature selection, and the classifier:

Model Algorithm Classifier Type CV Scoring Focus Evaluation & Observations
Logistic Regression ★ Linear Classifier Recall-Optimized Selected Final Model: Highest cross-validation recall; superior calibration and inference speed
Support Vector Classifier (SVC) Kernel Boundary Recall-Optimized Achieved top-tier CV recall alongside Logistic Regression; tested on held-out test data
Gradient Boosting Classifier Ensemble Boosting Recall-Optimized Strong predictive accuracy, but conservative churn decision boundary lowered raw recall
Random Forest Classifier Ensemble Bagging Recall-Optimized Tree ensemble voting naturally favored majority non-churn class, reducing sensitivity
K-Nearest Neighbors (KNN) Instance-Based Recall-Optimized Distance metric diluted across mixed categorical and scaled numerical features

Final Model Selection & Test Set Evaluation

Logistic Regression and SVC achieved the highest cross-validation recall among the tested models. Both were evaluated on the test set across multiple metrics. Logistic Regression was selected as the final model, prioritizing Recall for the Churn class:

86.42% Churn Recall (Primary)
70.66% Accuracy
60.90% Churn F1-Score
47.01% Churn Precision
84.20% ROC-AUC (0.842)
Confusion Matrix & Error Analysis

The confusion matrix was used to examine predictions across all four quadrants:

  • True Positives (Identified Churners): 86.42% of actual churners are successfully identified, allowing retention specialists to take targeted proactive action.
  • False Negatives (Missed Churners): Minimized to only 13.58% of churn cases. In churn prediction, False Negatives represent missed churners who leave the platform unnoticed, causing severe recurring revenue loss.
  • False Positives (Retained Customers Flagged): A 47.01% precision rate indicates manageable false alarms, which carry low operational cost in customer success workflows compared to losing recurring customer lifetime value.

Classification Threshold Analysis (Precision vs. Recall Trade-Off)

Different probability classification thresholds were tested to examine the trade-off between Precision, Recall, and F1-score:

Threshold Precision Recall F1-Score Operational Trade-Off Assessment
0.3 37.1% 95.3% 53.4% Highest raw recall (95.3%), but lower precision increases retention outreach overhead
0.4 41.1% 92.7% 57.0% Substantial recall boost (92.7%) with improved precision over 0.3
0.5 (Retained) ★ 47.0% 86.4% 60.9% Retained Production Threshold: Prioritizes high Recall (86.4%) while maintaining solid F1 balance
0.6 56.9% 71.8% 63.5% Higher F1-score (63.5%), but sharply reduces Recall from 86.4% down to 71.8% (misses ~28.2% of churners)
0.7 67.7% 53.2% 59.6% Conservative threshold; misses nearly half (46.8%) of actual churners

A threshold of 0.5 was retained for the final model because Recall is the primary metric in this project. Although a threshold of 0.6 produced a higher F1-score, it reduced Recall from 86.4% to 71.8%, which would allow too many actual churners to be missed.

ROC-AUC & Pipeline Serialization (Joblib)

The final Logistic Regression model achieved a ROC-AUC of 0.842 (84.20%). The ROC curve was plotted using predicted probabilities to evaluate the model's ability to distinguish between churn and non-churn customers across different classification thresholds.

The complete trained pipeline was serialized using joblib:

import joblib # Extract best estimator containing ColumnTransformer + SelectKBest + LogisticRegression final_model = logistic_grid.best_estimator_ # Serialize complete end-to-end pipeline joblib.dump(final_model, "telco_churn_model.pkl")

The saved pipeline contains the preprocessing, feature selection, and Logistic Regression model.
