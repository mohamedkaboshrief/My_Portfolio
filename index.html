Car Price Prediction — Technical Breakdown & Pipeline

Dataset & Problem Framing

Trained on the Kaggle Car Price Prediction Challenge dataset. The goal is to build an end-to-end regression model capable of accurately forecasting pre-owned car market valuations based on vehicle characteristics such as production year, mileage, engine volume, fuel type, gearbox, drive wheels, and vehicle specifications.

Data Cleaning & Feature Engineering Pipeline

  • Missing-Value Imputation & Type Conversion: Cleaned and imputed missing attributes, converted raw formatted numeric specifications into appropriate quantitative types.
  • Categorical Features & Combined Info: Merged car manufacturer and model fields into a cohesive vehicle descriptor to retain brand/model lineage.
  • High-Cardinality Target Encoding: Applied Target Encoding to the high-cardinality "Car" feature (hundreds of distinct makes/models) using Category Encoders, preserving price variance without dimensionality explosion.
  • Outlier Management: Performed outlier detection and eliminated extreme price anomalies that severely skewed regression loss distributions.
  • Train / Test Split: Segregated held-out test data to ensure unbiased final model evaluation.

Model Comparison (5-Fold Cross-Validation on 8 Regressors)

Eight regression models were evaluated using 5-Fold Cross-Validation with R² as the evaluation metric:

Model Algorithm Category Mean CV R² Evaluation Notes
Linear Regression Linear Baseline 0.2623 Baseline regressor; underfitted complex non-linear pricing relationships
SGD Regressor Gradient Descent -2.49 × 10²⁹ Severe gradient divergence due to unclipped high-magnitude variance
Lasso Regression (L1) Regularized Linear 0.2624 Enforced feature sparsity; restricted by linear assumptions
Ridge Regression (L2) Regularized Linear 0.2624 Mitigated multicollinearity among correlated specs; equivalent to Lasso
Random Forest Regressor ★ Ensemble Bagging 0.7447 Selected Best Model — Highest mean CV R²; selected for hyperparameter tuning
Gradient Boosting Regressor Ensemble Boosting 0.6531 Strong non-linear predictive capacity; second highest baseline score
Decision Tree Regressor Tree-based 0.6020 Captured hierarchical splits but susceptible to high variance and overfitting
K-Nearest Neighbors (KNN) Instance-based 0.3587 Degraded distance metrics across high-dimensional sparse representations

Hyperparameter Tuning (GridSearchCV)

GridSearchCV was utilized to tune the Random Forest Regressor with 5-Fold Cross-Validation using R² as the scoring metric across 24 parameter combinations:

  • n_estimators: [300, 500]
  • max_depth: [8, 10, 15]
  • min_samples_split: [2, 5]
  • min_samples_leaf: [1, 2]
  • max_features: [0.8]

Best GridSearchCV Score: R² = 0.7431

RandomForestRegressor( n_estimators=500, max_depth=15, min_samples_split=2, min_samples_leaf=1, max_features=0.8, random_state=33 )

Final Model Results on Unseen Test Set

The tuned Random Forest Regressor was evaluated on the held-out test set, achieving a Test R² of approximately 75.2%:

0.9394 Train R²
0.7523 Test R² (~75.2%)
4,467.51 Mean Absolute Error (MAE)
2,440.52 Median Absolute Error
8.04 × 10⁷ Mean Squared Error (MSE)

The MAE of 4,467.51 indicates that model predictions deviate from actual market prices by approximately $4,468 on average. The Actual vs Predicted evaluation plot demonstrates strong alignment along the diagonal reference line across diverse vehicle price points.

Telco Customer Churn — Technical Breakdown & Pipeline

Dataset & Business Problem Framing

Trained on the Kaggle Telco Customer Churn dataset comprising 7,043 customer records and 21 attributes. The objective is binary classification: predicting whether a telecommunications subscriber will cancel their service (Churn = 1) or remain subscribed (Churn = 0). Because unpredicted churn leads directly to customer and revenue loss, Recall was selected as the primary optimization metric to capture as many at-risk customers as possible.

Data Cleaning & Feature Encoding Pipeline

  • Missing-Value Imputation & Casting: Converted TotalCharges into numerical format; estimated missing values using service tenure and monthly bill distributions. Final cleaned dataset: 7,040 rows and 20 columns.
  • Identifier Removal: Removed customerID to ensure the model learns true behavioral patterns rather than arbitrary database keys.
  • Strategic Multi-Method Encoding:
    • Label Encoding: Applied to binary categorical features (Partner, Dependents, PhoneService, etc.).
    • One-Hot Encoding: Applied to nominal multi-category features (PaymentMethod, InternetService, Contract lines).
    • Ordinal Encoding: Applied to Contract (Month-to-month → 0, One year → 1, Two year → 2) preserving intrinsic commitment hierarchy.
    Processed feature space expanded cleanly to 30 features.
  • Outlier & Distribution Analysis: Evaluated box plots across continuous features (tenure, MonthlyCharges, TotalCharges) to verify data integrity.
  • Train / Test Split: Stratified 80/20 train-test partition to safeguard uncompromised test set validation.

Model Comparison (5-Fold Cross-Validation on 6 Classifiers)

Six classification algorithms were benchmarked under 5-Fold Cross-Validation using Recall as the primary evaluation metric:

Model Algorithm Category Mean CV Recall Evaluation Notes
Gaussian Naive Bayes ★ Probabilistic Classifier 0.723 Selected Best Model — Highest baseline recall; effectively captured conditional churn likelihood
Logistic Regression Linear Classifier 0.537 Standard linear baseline; balanced accuracy but moderate recall on churners
Decision Tree Tree-based 0.500 Prone to false negatives on unpruned leaf splits
Random Forest Ensemble Bagging 0.461 Biased toward majority class (non-churners), lowering recall
K-Nearest Neighbors (KNN) Instance-based 0.405 Degraded distance calculation across sparse one-hot dimensions
Support Vector Classifier (SVC) Kernel Method 0.000 Failed to detect minority churn class under default decision threshold

Hyperparameter Tuning (GridSearchCV)

GridSearchCV with 5-Fold Cross-Validation was executed to optimize Gaussian Naive Bayes:

  • Optimized hyperparameter: var_smoothing
  • Best hyperparameter setting: var_smoothing = 1e-08
  • Best Cross-Validation Recall: 0.7448 (improved from 0.723)
GaussianNB( var_smoothing=1e-08 )

Final Model Results & Confusion Matrix (Unseen Test Set)

The tuned Gaussian Naive Bayes model was evaluated on the held-out test set, identifying 301 out of 380 actual churn cases (~79% Recall):

79% Churn Recall
74.93% Test Accuracy
75.11% Train Accuracy
63% Churn F1-Score
52% Churn Precision
Confusion Matrix Analysis
Predicted: No Churn (0) Predicted: Churn (1)
Actual: No Churn (0) 754 (True Negatives) 274 (False Positives)
Actual: Churn (1) 79 (False Negatives) 301 (True Positives ★)

The model correctly flags 79% of churners (301 of 380), empowering proactive retention campaigns. The moderate precision (52%) represents an intentional and advantageous trade-off in customer retention economics, where the cost of extending retention perks to non-churning customers is far lower than the recurring revenue loss of an undetected churned customer.
